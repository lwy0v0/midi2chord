# Loop 和声提取 · 可行性分析

> 定位（按你的原话收敛）：**从一段 loop 里提取「调性 + 和弦进行 + 和声节奏」，供你拓展创作。**
> 明确不做：给旋律配和弦、和弦替换建议、自动生成新 MIDI。

> 前置文档：[MIDI 写作常见手法](./MIDI写作手法清单.md)（实况）、[和弦语汇](./和弦种类与处理方法清单.md)（名词表）、
> [MIDI 扩展调研](./和弦识别与MIDI扩展调研.md)（分段方案）。语料：[testdata/midi/](../testdata/midi/语料清单.md)。

## 0. 结论摘要

| 判断 | 结论 |
| --- | --- |
| **整体可行性** | **可行**。八个环节里七个有成熟做法或已有实现，没有需要研究突破的东西。 |
| **最大风险** | 不是解析，也不在和弦识别，而是 **① 短 loop 的调性歧义**、**② 和声节奏的分段**。 |
| **建议路径** | 先花**半天**做"调性判定"的单独验证实验；通过（top-1 ≥ 80%）再投入分段。反过来做会白费。 |
| **工作量** | 功能可用约 **5–9 人天**（不含 UI）；其中约 40% 的时间会花在调参与真值标注上，而不是写代码。 |
| **不能承诺的** | 多轨完整编曲（如 17 轨大乐队）一次全对。只能做到"逐轨给结果 + 明确标注不确定"。 |

一句话：**技术上不是难题，工程上是"证据不足"的问题**——4 小节里能拿来判调性的证据本来就少，方案要围绕"如何在证据不足时仍然给出一致、可解释、可拒答的结果"来设计。

## 1. 目标与成功标准

必须先量化"做成了"，否则无法判断可行性。

| 输出项 | 指标 | 建议阈值 | 为什么是这个阈值 |
| --- | --- | --- | --- |
| **调性** | 在手工标注的 N 条 loop 上 top-1 命中率 | ≥ 80% | 低于 80% 用户会直接不信；关系大小调混淆会计入错误 |
| **和弦** | 按时长加权的 root 准确率 | ≥ 75% | 只要根音对，用户就能用；性质（大/小/七）错还能接受 |
| **和弦性质** | 按时长加权的 majmin 准确率 | ≥ 65% | 比 root 宽松，因为七音/九音常省略 |
| **和声节奏** | 段边界误差 ≤ 半拍的比例 | ≥ 70% | "一小节一个"和"一小节两个"必须能分开 |
| **拒答** | 单声部素材输出和弦的比例 | **必须 0%** | 硬性要求：宁可说"判不出"，不能编 |

> 阈值为建议值，需要和你对一次。**这些数字决定项目是否值得继续，所以在写代码前应该先测出来。**

## 3. 关键不确定性：五个必须先回答的问题

### Q1 —— 4 小节的调性，到底能不能判准？（**最致命**）

**已知反例**：`Cymatics Bonus MIDI - Am_110bpm`

```text
和弦序列判定：C major 0.91
音级分布判定：A minor 0.70
文件名标注：  Am
```

三个信号打架。这不是 bug，是**短素材的固有歧义**：C 大调与 A 小调共用同一套音，区分它们靠"主音落在哪里"，而 4 小节里主音可能只出现一次、甚至不出现。

**为什么这是最致命的**：调性是所有后续输出（罗马数字、进行描述、拓展建议）的基准。调错一级，整套结论全偏。

**可能的对策**（都需验证）：
1. **低音线索优先**：loop 里最低音的音级分布，比整体音级分布更能指示主音（bass 落主音的概率高）；
2. **首尾和弦**：loop 通常从主和弦或从属和弦出发；首尾都落在 C 和弦 → C 大调；
3. **第三音**：大调用 `E`、小调用 `Eb` 作为三音，看哪个是稳定的长音；
4. **输出双解**：当两个候选差距 < 阈值时，**同时给出**"C 大调 / A 小调"，并说明"这条 loop 是模糊的"。这比强行二选一诚实，也更符合实际创作场景（关系大小调本来就可以互换使用）。

> 我的判断：**4（输出双解）是必须的**，1–3 是提高准确率的手段。而且"这条 loop 调性模糊"本身就是有用的信息。

### Q2 —— 固定网格能切对和声节奏吗？（**第二致命**）

**已知证据**：

| 素材 | 1 拍窗口 | 整小节窗口 | 结论 |
| --- | --- | --- | --- |
| 柱式 loop | 好 | 抹平半小节换和弦 | 需要细分 |
| 琶音轨（3393 音符） | **碎成几百个假和弦** | 碰巧正确 | 必须聚合 |
| 极稀疏和声层（0.55 音/小节） | 大量空窗 | 好 | 需要大窗 |
| 切分 comping（52ms stabs） | 边界错位 | 抹平 | 必须自适应 |

**结论：任何固定窗口都会在一类素材上系统性失效。** 这已经被实测证实，不是推测。

**对策**：不是"选一个更好的固定窗口"，而是"边界候选 + 全局最优"（Temperley 路线）。
代价是实现复杂度上升一档，且需要调参。

**降级方案**（如果全局最优做不出来）：**输出"多粒度结果"**——同时给"按小节"和"按半拍"两个版本，让用户自己看哪个对。这把算法问题转成了交互问题，成本低很多。

### Q3 —— 单轨混装能不能分出旋律？

`Damascus` 单轨钢琴：968 音符、`A2–G7`、跨 5 个八度。左手伴奏 + 右手旋律 + 可能还有内声部全在一轨。

**主判据不是音区，是时值。** 采样包里混装的典型形态是：**和弦音长、旋律音短而零散**。
这比音区可靠得多，因为旋律会上下跑，音区判断不可靠。

具体做法（三条判据叠加，按可靠度排序）：

| 判据 | 做法 | 强度 |
| --- | --- | --- |
| **时值** | 时值 ≥ 半拍的音优先当和弦音；≤ 1/16 拍的孤立音判为旋律 | 强 |
| **同起点聚簇** | 同一时刻（±2 刻度）起音 ≥ 2 个 → 和弦；孤立单音 → 旋律 | 强（能救回点状和弦） |
| **声部连续性** | 一串音如果音程接近、时间连续、构成一条线 → 旋律（兜住"旋律长音"） | 中 |

> 注意：**要加权，不要硬分层**。给每个音算一个"和声权重"（时值 × 是否成簇），
> 让和弦识别按权重取舍，低权重的音进 `排除音`。硬分层会把"旋律长音"和"点状和弦"直接判死。

**仍然会失败的三类**（必须接受，靠置信度提示）：

1. **旋律里有长音**（副歌保持音 1–2 拍）→ 会被当和弦音，只能靠"连续性"救一部分；
2. **点状和弦**（大乐队钢琴 50 毫秒的 stabs）→ 时值上像旋律，靠"同起点多音"救；
3. **琶音**（每个音都短，但整体是和弦）→ 需要靠"音集合在同一模板下闭合"反向聚合。

> 判断修正：这条**比原先估的乐观**——因为时值是强判据，而采样包的混装形态恰好符合
> "长和弦 + 短旋律"。风险等级从"中高"降为"中"。

### Q4 —— 无根音 / 省略音现在要不要做？

采样包和弦层常常缺根音、缺五音（`NSB_Pad` 音域只有一个八度）。

但**低音轨通常存在**（贝斯轨 / 和弦层的低音），可以用来补根音线索。

**判断**：
- 若走"逐轨分角色"，和声层 + 贝斯层合并后音集合基本完整 → **不必先做无根音推断**；
- 只有单轨混装时才需要无根音推断 → 而那种情况本来就要人工核对。

→ **结论：无根音推断（原 P0 的那个改造）不是本功能的阻塞项**，可以往后放。这会省下不少工作量。

### Q5 —— 文件名弱真值够用吗？

49% 带调性、30% 带 BPM、59% 带角色。

**够用作"筛选用"**：可以快速分类、批量跑、发现异常。
**不够用作"判定用"**：`Am_110bpm` 就是反例。

→ **需要手工标注 10–20 条作为真正的基准**。这是本功能最该先投入的"非代码工作"。

## 4. 逐环节可行性评估

| # | 环节 | 难度 | 现有基础 | 主要风险 | 可行性 |
| --- | --- | --- | --- | --- | --- |
| 1 | SMF 解析 | 低 | **已实现**（零依赖，含单测） | 畸形文件（缺 note-off、未知块）已有兜底 | ✅ 高 |
| 2 | tempo / 拍号 / 弱起 | 低 | 已实现；缺 tempo 时有回退与告警 | 无 tempo 文件只能按 120 算绝对时间 | ✅ 高 |
| 3 | 剔除鼓轨 | 低 | 通道 9 + 轨道名关键词 | 无 | ✅ 高 |
| 4 | 分角色（贝斯/和声/旋律） | 中 | 音域 + 复音度 + 文件名/轨道名 | 单轨混装误判 | ⚠️ 中 |
| 5 | 网格剖面 | 中 | 16 分格 + 活动音集合 + 低音 | 网格粒度选择需实测 | ⚠️ 中 |
| 6 | 分段（和声节奏） | **高** | 启发式边界（低音变化 / 音集合变化） | **系统性失效**（见 Q2） | ⚠️ 中低 |
| 7 | 基础和弦折叠 | 中 | 独立实现了"骨架三/七和弦 + tensions + 斜杠" | 折叠规则需用真实素材校准 | ⚠️ 中 |
| 8 | 调性判定 | **中高** | 复用现有 24 调打分 + 新增音级分布判据 | **关系大小调歧义**（见 Q1） | ⚠️ 中 |
| 9 | 罗马数字 | 低 | 直接复用 `progression::analyze_role` | 依赖 7、8 正确 | ✅ 高 |
| 10 | 拒答（单声部） | 低 | 复音度判定 | 无 | ✅ 高 |

**汇总**：1/2/3/9/10 是"照着做就行"；4/5/7/8 是"要调，但路径清楚"；6 是**唯一真正需要方案选择的环节**。

## 8. 建议的验证顺序（先证伪，再投入）

```text
第 1 步（半天）：手工标注 10–20 条 loop 的真值（调性 + 逐段和弦）
第 2 步（半天）：只跑调性判定，算 top-1
    ├─ ≥ 80% → 继续
    └─ < 80% → 先解决调性（多判据/双解），或调整产品形态
第 3 步：跑基础和弦（固定小节窗口），算 root / majmin 准确率
第 4 步：只有前两步达标，才投入分段算法（P2 是最大工作量）
```

**为什么是这个顺序**：调性和和弦是"产品地基"，分段是"精度优化"。地基不牢就先优化分段，等于在错误的结论上做精修。

## 9. 第一次实测：已经跑通了

代码已写完并跑通 17 个语料文件。**这是一次未调参的跑分，不代表最终能力**，但足以判断方向对不对。

### 9.1 结果

| 语料 | 判定 | 和弦进行 | 评价 |
| --- | --- | --- | --- |
| `Cymatics - Lofi MIDI 1 - C Maj` | **C 大调 100%** | `Cmaj7 → Fmaj7 → Cmaj7 → Fmaj7` | ✅ **完全正确**（文件名 C Maj 吻合，罗马数字 I–IV 也对） |
| `Cymatics Bonus MIDI - Am_110bpm` | C 大调 78%／A 小调 78% | `Am7 → Cmaj7/D → Fmaj7 → …` | 🟡 关系大小调并列（诚实），和弦基本对 |
| `Cymatics - Lofi MIDI 10 - C# Min` | E 大调 79% | `A → B → E → Bmaj7 → Emaj7` | 🟡 判成关系大调（真实应为 C# 小调） |
| `GxD MIDI 33d CHORDS` | 降 E 大调 46% | `B → G#m → D# → E → G#m → D#` | 🟡 和弦看着合理，调性置信度低 |
| 4 个单声部文件 | **拒答** | — | ✅ 正确拒答（贝斯/旋律不硬凑和弦） |
| `Damascus`（单轨钢琴，968 音） | E 大调 35%／A 小调 | `Am → A → Fmaj7 → F#m → G#m → …`，90 段 | ❌ 碎片化，调性不可信 |
| `JustJazz`（17 轨编曲） | C 大调 19% | 杂糅 | ❌ 多轨整体分析必错（预期之内） |

### 9.2 三个修掉的 bug（都是实测才暴露的）

| bug | 症状 | 原因 |
| --- | --- | --- |
| 覆盖率分母用错 | 和弦音被当成外音，输出一堆 `?` | 用"所有音之和"归一化，5 个音均分后每个都低于门槛；应除以**段长** |
| 转成内部和弦时只给了根音 | `Cmaj7` 在降 B 大调里没被扣分，调性判成降 B | 调性打分靠"全部音是否在调内"，缺了三音就丢失关键信息 |
| 单声部判定用最大值 | 贝斯有同音重叠 → 误判成有和声 → 硬凑和弦 | 改用"平均值低 **且** 最大值也低"的组合判据 |

### 9.3 关于"时值判据"的结论（你给的那条信息）

**有效，而且是最有用的一个判据。** 实测证据：

- `A → B → E` 这类段里，被排除到"外音"的正是旋律音（`A` 段排除 `F# G#`，只留 `C# E` 构成 A 大三和弦）；
- 柱式和弦 loop 上一刀切得干干净净，没有把旋律音卷进和弦。

但它**不是万能**，实测确认了三类反例（与预判一致）：

| 反例 | 现象 | 修法方向 |
| --- | --- | --- |
| **点状和弦** | 50–300 毫秒的 stabs 平均复音度太低，被判成单声部 | 靠"同起点多个音"救（判据已有，阈值要调） |
| **琶音** | 一次只响一个音，被判成单声部 | 需要"跨时间聚合"：把连续短音按和弦模板闭合 |
| **稀疏 pad** | `NSB_Pad_Chords_02` 被误判成单声部 | 同上，需要看"音集合是否成和弦"而非只看向时性 |

### 9.4 结论

| 环节 | 状态 |
| --- | --- |
| 解析、分层、拒答、柱式和弦提取 | **可用** |
| 关系大小调判定 | 需要"双解输出"（已在设计里），不能指望单点判定 |
| 分段粒度 | **不达标**：90 段/57 小节，太碎，需要提高最短段并加全局平滑 |
| 琶音 / 点状 / 稀疏 pad | **不达标**，属于同一类问题：需要"跨时间聚合" |

> 一句话：**"能不能提取"已经是"能"，"提得准不准"还需要按 §8 的顺序逐项调。**
> 且这次跑分最大的价值不是分数，而是确认了优先级——分段与聚合是主要工作量，调性要靠多判据兜底。

### 9.5 第二次迭代：改成"全局解码"（关键的一步）

第一版的思路是「先分层 → 再猜边界 → 每段独立识别 → 最后判调」，四个环节各自都可能错，
且错会一路传下去。改成：

> **不猜分段、不剪枝，直接枚举「调 × 调内级数和弦」，用动态规划求整条最优序列。**

思路来源是"算力不是约束"这个判断：4 小节的 loop，**24 个调 × 7 个级数 × (三和弦 | 七和弦) = 336 个候选**，
每个调跑一遍动态规划，代价 = Σ(每格匹配代价 + 换和弦代价)，总运算量只有几十万次，Rust 毫秒级。

好处有三个：

1. **调性和和弦序列一起解出来**，不再"先定调再识别"（那一步错就全错）；
2. **段边界是解码的副产物**——连续落在同一个候选上的格就是一段，不用再猜窗口；
3. **"一小节两个和弦"由解码器自己决定**，不需要固定网格假设。

代价设计：
- 缺根音、缺三音：重罚（这是和弦身份）；缺五音：轻罚（采样包里常省略）
- 多余音（明显响着却不属于该和弦）：中等惩罚
- 低音正好是根音：加分
- 换和弦：落在强拍便宜、弱拍贵；同根音加七音（`C → C7`）便宜

结果对比（同一批语料）：

| 语料 | 第一版（启发式） | 第二版（全局解码） | 变化 |
| --- | --- | --- | --- |
| `Lofi MIDI 1 - C Maj` | C 大调 100%，4 段 | C 大调 53%，`Cmaj7→Fmaj7→Cmaj7→Fmaj7` | 和弦仍对；置信度更保守 |
| `Lofi MIDI 10 - C# Min` | **E 大调 79%**（错） | **G# 小调 45%**，`C#m7→G#m7→B→F#→E→D#m` | ✅ 纠正 |
| `Am_110bpm` | C 大调 78%，7 段带斜杠 | C 大调 53%，`Am7→Em7→Fmaj7→Dm7→Cmaj7` | ✅ 序列明显更顺 |
| `GxD 33d CHORDS` | 降 E 大调 46%（与音级分布矛盾） | G# 小调 53%（**与音级分布一致**） | ✅ 自洽了 |
| `Zenhiser琶音 1-4` | 降 D 大调，1 段 | C 小调，`Cm7→D#→Cm→D#→G#→…` | ✅ 与另一工具的分小节结果吻合 |
| `Damascus`（单轨钢琴） | E 大调 35%，**90 段** | C 大调 45%，序列规整 | ✅ 碎片化大幅缓解 |
| 单声部 4 个文件 | 拒答 | 拒答 | 保持 |

### 9.6 关于"调性好不好判断"的结论

实测数据支撑了一个更细的判断：**调性的"最优解"是可靠的，但"最优与次优的差距"很小时不宜硬报。**

- 短 loop 里，24 个调常常有 3–5 个代价很接近——因为**关系调、平移调的和弦集合高度相似**。
  这不是算法缺陷，是信息量的客观限制。
- 因此置信度普遍落在 45–53%，这是**诚实的读数**，比第一版动辄"100%"更可信。
  第一版的高分是"只算音级贴合度"造成的虚高。

**一个有用的副产品**：既然关系大小调的和弦集合相同（C 大调的 `C-Am-F-G` 与 A 小调的 `III-i-VI-VII` 是同一组），
那么**调性判错关系大小调时，和弦名依然是对的**，只有罗马数字编号不同。
所以在展示上可以把"和弦进行"和"功能/罗马数字"分开呈现——前者更可靠，后者依赖调性。

### 9.7 验证：「一小节两个和弦」到底能不能识别

采样包里很难找到"已知答案 + 一小节多和弦"的素材，所以直接合成一个测试文件
（`testdata/midi/05-合成测试/和声节奏-两和弦与四和弦.mid`，4 小节，答案写死）：

| 小节 | 实际内容 | 识别结果 | 结论 |
| --- | --- | --- | --- |
| 1 | `C`（2 拍）+ `F`（2 拍） | `C` 2.00 拍 / `F` 2.00 拍 | ✅ 一小节两个和弦 |
| 2 | `C` + `Am` + `F` + `G`（每拍一个） | 各 1.00 拍，四个都对 | ✅ 一小节四个和弦 |
| 3 | `C`（整小节 4 拍） | `C` 4.00 拍 | ✅ 长和弦不被切碎 |
| 4 | `F`（2 拍）+ `G`（2 拍） | `F` 2.00 拍 / `G` 2.00 拍 | ✅ |

**9 段全部正确，起止位置与时长精确到拍**；调性判 C 大调也正确。

结论：**和声节奏是解码器自己解出来的，不需要预设"一小节一个和弦"或固定窗口。**
这也正是第二版改全局解码的直接收益。

### 9.8 音符级标注与代表音

为了让"结果能被肉眼核对"（后面要做钢琴卷帘可视化），输出里加了两层：

- **每个音符一条记录**：音高（带八度）、起始拍、时长、力度、所属段、角色（根音/三音/五音/七音/延伸音/旋律/段外）、判定权重、是否成簇；
- **每段一组代表音**：同一个和弦音**只取一个**具体音符（同音高类里时值最长、其次音高最低），并记录该音高类在本段重复了几次。

实测（合成文件第 2 小节 `Am`）：

```text
2.2  Am  vi  1.00 拍  根=A 低音=A  音:[C E A]
    代表音：A3-根音(0.90)  C4-三音(0.90)  E4-五音(0.90)
```

> 这一层顺手抓到一个真 bug：小三和弦的五音曾被标成"延伸音"——
> 因为三和弦骨架表里「小三」和「减三」共用了同一个五音偏移（6），
> 而小三的五音是 7。已修。

### 9.9 音符级识别：三条判据是怎么定的

第一版只用了「时值短 + 孤立起音」一条，结果在标准谱型上完全失效——
实测 `Cymatics - Lofi MIDI 2 - C Maj`（8 小节，下面和弦、上面旋律，非常分明）：
**50 个音全部被标成和弦音，旋律一个都没认出来。**

原因：旋律音是八分音符（0.5 拍），而判据卡的是 `< 0.35 拍`。

改成三条判据，按优先级：

| 优先级 | 判据 | 为什么 |
| --- | --- | --- |
| 1 | **上层 + 短于和弦主体** | "下面和弦、上面旋律"是标准谱型，最可靠 |
| 2 | 孤立起音 + 时值很短 | 抓零散的单音（琶音之外的装饰） |
| 3 | 音高类属于骨架 | 兜底：既不成层也不短的，按音级归角色 |

**"上层"怎么切**（`find_upper_split`）：两个信号一起用，只用任何一个都会失灵。

1. 音高上有一个空隙（≥ 5 半音）；
2. 空隙**上方**的音平均时值不超过下方的 50%，且总时值占比也 ≤ 50%。

分档处理是关键：

- 上层有 **2 个以上**音高 → 音隙 ≥ 5 即可；
- 上层只有 **1 个**音高 → 要求音隙 ≥ 12（一个八度），否则纯和弦/pad 里一个偏高的音就会被误判。

> 这条分档是实测逼出来的：先按"上下各至少 2 个音高"收紧，纯和弦文件正常了，
> 但旋律只有一个音高的段落（如 `B5`）又漏了；最后按"单音上层用更严条件"才两头都顾上。

**调性也跟着修了**：`Dm7 - G7 - Bm7b5 - Am7` 这个进行，关系大小调（C 大调 / A 小调）
的和弦集合完全一样，DP 靠和弦匹配永远分不出——是**主音证据**（结束和弦、开头和弦、
主和弦占比、低音落点）把它定成 A 小调的（`iv - VII - iiø - i`，结束在主和弦）。

改前 → 改后（同一文件）：

| | 改前 | 改后 |
| --- | --- | --- |
| 调性 | C 大调 45% | **A 小调 68%** |
| 罗马数字 | ii - V - viiø - vi | **iv - VII - iiø - i** |
| 音符分类 | 50 和弦音 / **0 旋律** | 36 和弦音 / **14 旋律** |

全语料复跑（防止修一个坏一个）：

| 文件 | 类型 | 结果 |
| --- | --- | --- |
| `GxD 33d CHORDS` | 纯和弦 | 202 和弦音 / **0 假旋律** ✅ |
| `NSB_Pad_Chords_05` | 窄音域 pad | 20 / 0 ✅ |
| `Zenhiser琶音 1-4` | 琶音 | 225 / 0 ✅（琶音音本来就是和弦音） |
| `Lofi MIDI 1` | 混装 | 26 / 13 ✅ 置信度同时从 53% 升到 83% |
| `Damascus`（单轨钢琴） | 重混装 | 827 / 141 ✅ 调性从 C 大调改为 A 小调 |

这两条都固化成回归测试了：`upper_voice_is_separated_as_melody`、`relative_minor_is_chosen_by_ending_chord`。
