# 前端模块地图

> 目的：**要改某个东西时，一眼知道该动哪个文件**，不用翻遍整个目录。
> 拆分的核心原则只有一条：*一个文件只因为一种原因被修改*。

---

## 一、目录与职责

```
src/
├── App.vue                    外壳：主题 / 语言 / 两个 tab 的编排
├── main.ts                    挂载
├── types.ts                   后端 JSON 契约的类型（与 Rust 结构一一对应）
│
├── api/                       与后端通信。**只做调用与错误归一化**
│   ├── analyze.ts             和弦序列入口（含 AnalysisError、运行时检测）
│   └── midi.ts                MIDI 入口（传字节、拿结果）
│
├── composables/               状态与流程。**不含界面**
│   ├── useChordGrid.ts        和弦输入网格（行列、校验、去重提示）
│   ├── useChordAnalysis.ts    和弦序列的分析流程
│   └── useMidiAnalysis.ts     MIDI 的分析流程（选文件 → 结果 / 错误）
│
├── adapters/                  **业务 → 通用组件的翻译层**
│   └── roll.ts                分析结果 → 卷帘窗的 notes/segments/配色/图例
│
├── constants/                 常量与纯函数（改拼写、改配色只动这里）
│   ├── notes.ts               音名选项（键盘输入那套用）
│   └── music.ts               音名、音高 → 名称、角色中文名、角色配色
│
├── components/
│   ├── PianoRoll.vue          ★ 通用钢琴卷帘窗（零业务依赖，可整份搬走）
│   ├── MidiAnalysisPanel.vue  MIDI 面板的**编排层**（只接线，不写样式细节）
│   ├── midi/                  MIDI 面板的展示小组件（每个只管一件事）
│   │   ├── MidiDropZone.vue   拖放 / 选文件
│   │   ├── KeySummary.vue     调性 + 基本事实
│   │   ├── NoteLegend.vue     图例（通用：只认 {key,label,color}[]）
│   │   ├── SegmentTable.vue   和弦段列表
│   │   └── SegmentDetail.vue  选中段详情
│   ├── AnalysisPanel.vue      和弦序列的结果面板
│   ├── ChordInputGrid.vue     和弦输入网格
│   ├── ChordSizeControls.vue  行列数控制
│   ├── KeyCandidateCard.vue   候选调卡片
│   └── ChordChip.vue          和弦标签
│
├── utils/format.ts            展示格式化（和弦序列那套）
└── styles/global.css          全局样式（尽量少）
```

## 二、依赖方向（单向，不许回环）

```
App.vue
  ↓
components/MidiAnalysisPanel.vue        ← 编排层
  ↓            ↓              ↓
components/midi/*.vue   adapters/roll.ts
  ↓                        ↓
constants/music.ts      components/PianoRoll.vue（通用，不依赖任何业务）
  ↓
types.ts

api/midi.ts   ← 只被 composables 用
composables/useMidiAnalysis.ts   ← 只被 App.vue 用
```

三条硬规矩：

1. **`PianoRoll.vue` 不 import 项目里的任何东西**——只依赖 Vue。它一旦引用了业务类型，就搬不走了。
2. **展示小组件不互相引用**，只通过 props / emits 通信。要共享逻辑就往上提到 `adapters/` 或 `composables/`。
3. **`api/` 里不放展示逻辑**（不要出现"哪个颜色""怎么措辞"）。

## 三、改什么 → 动哪里

| 想改的东西 | 改这个文件 |
| --- | --- |
| 换个配色 | `constants/music.ts` 的 `NOTE_ROLE_COLORS` |
| 音名要用降号（`Bb` 而不是 `A#`） | `constants/music.ts` 的 `pitchName()` |
| 角色中文名（"根音" → "根"） | `constants/music.ts` 的 `NOTE_ROLE_LABELS` |
| 卷帘窗的颜色 / 格子大小 / 提示条 | `components/PianoRoll.vue`（自己的 props 与 scoped 样式） |
| 卷帘窗怎么画（加缩放、加拖动） | 只改 `PianoRoll.vue`，别处不受影响 |
| 后端返回的字段变了 | `types.ts` + `adapters/roll.ts`（后者是唯一翻译层） |
| 调性卡上多显示一行 | `components/midi/KeySummary.vue` |
| 和弦段表格加一列 | `components/midi/SegmentTable.vue` |
| 选中段的详情怎么排版 | `components/midi/SegmentDetail.vue` |
| 投放区文案 / 支持更多扩展名 | `components/midi/MidiDropZone.vue` |
| 面板整体顺序（先表还是先卷帘窗） | `components/MidiAnalysisPanel.vue`（只有编排） |
| 上传失败怎么提示 | `api/midi.ts`（错误码）+ `MidiAnalysisPanel`（显示） |
| 加一个 tab / 调整 tab 顺序 | `App.vue` |
| 分析流程（防抖、并发） | `composables/useMidiAnalysis.ts` |

## 五、还有两处「知道但没拆」

诚实记一下，不是漏了：

1. `PianoRoll.vue` 内部有自己的一份音名表（没有 import `constants/music.ts`）。
   这是**故意**的：为了可移植。代价是改音名拼写要改两处。如果哪天不再需要移植，可以合并。
2. `App.vue` 里同时持有两套状态的编排（和弦网格 + MIDI）。
   目前两个 tab 互不相干，耦合很浅；如果以后交互变复杂（比如"把 MIDI 结果填进键盘输入"），
   应该抽一个 `useWorkspace` 来管跨 tab 的状态，而不是往 `App.vue` 里堆。
