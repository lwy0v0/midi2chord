# MIDI 写作常见手法 · 实况清单

> 目的：把"采样包 / DAW 导出 / 真实编曲"里 MIDI 实际长什么样、为什么长这样、分析器要为哪些情况准备预案，一次列全。
> 数据来源：本机采样库 `D:\data\fl\采样包`，22,028 个文件中的 **927 个 `.mid/.midi`**，抽 17 个做实测（语料见 [testdata/midi/语料清单.md](../testdata/midi/语料清单.md)）。
> 姊妹文档：[和弦语汇与和声处理方法](./和弦种类与处理方法清单.md)（名词表）、[MIDI 扩展调研](./和弦识别与MIDI扩展调研.md)（现状与分期）。

---

## 0. 一句话结论

**采样包里的 MIDI 大多不是"和弦进行"，而是"一个声部的一次演奏"。**
把它当柱式和弦进来看，九个维度上都会翻车——音符密度差 40 倍、音域跨度差 5 倍、近一半文件里根本没有完整和弦。

## 1. 先看实况：927 个文件的分布

| 维度 | 实测 | 含义 |
| --- | --- | --- |
| 文件名带**角色**词 | 551 / 927（**59%**） | 文件名本身就是轨道说明，可作先验 |
| 文件名带**调性** | 456 / 927（**49%**） | 可作弱真值做自动校验（但有例外，见 §4.6） |
| 文件名带 **BPM** | 278 / 927（**30%**） | 常常与文件内 tempo 脱钩 |
| 角色词频（前 8） | melody 163 · bass 130 · chords 88 · synth 53 · piano 40 · lead 23 · pluck 19 · arp 18 | **只有 88 个文件自称"和弦"**，绝大多数是旋律/贝斯/音色层 |

> 这条数据决定了产品定位：MIDI 输入功能**必须能拒答**（"这个文件里没有和弦信息"），
> 而不是对任何 MIDI 都吐一串和弦名。

## 2. 五种素材形态

| 形态 | 典型代表 | 结构 | 分析策略 |
| --- | --- | --- | --- |
| **单轨 loop** | Lofi MIDI 1（39 音符/4 小节） | 一轨，可能左手+右手+旋律混在一起 | 按音区分层 → 低层当和弦，高层当旋律 |
| **分轨 kit** | GxD / NSB（`BASS.mid`、`CHORDS.mid`、`LEAD.mid` 各一个文件） | 一个文件=一个角色 | **只分析 CHORDS/PAD/KEYS 类文件**；BASS 单独用来定低音 |
| **琶音/合成器层** | Zenhiser「Arpeggio」3393 音符 | 单轨高速琶音 | 必须按和弦事件聚合，且要合并低音轨 |
| **Song starter** | Zenhiser「Limitless」5 轨 6644 音符 | 多层：和声层 + 琶音 + 音色层 + fills | 分轨 → 逐轨判角色 → **合并和声相关轨** |
| **完整编曲** | JustJazz（17 轨/5015 音符）、Damascus（单轨钢琴 968 音符） | 真实配器 | 分轨 + 声部分离 + 全局解码 |

## 3. 与"柱式和弦进行"的九个差异（全部有实测）

| # | 维度 | 柱式和弦 | 采样包 MIDI 实况 | 证据 |
| --- | --- | --- | --- | --- |
| 1 | **密度** | 每小节 3–4 音同时响 | 0.55 ～ 23 音符/小节（**差 40 倍**） | Zenhiser「Chords Harmonies」84 音符/152 小节；GxD 202 音符/8.7 小节 |
| 2 | **完整性** | 和弦音齐全 | 一半文件没有完整和弦；连"和弦轨"也只弹和声层的少数音 | 和声层轨 84 音符/152 小节（0.55 音每小节）；59% 文件名是旋律/贝斯 |
| 3 | **时间展开** | 同时发声 | 琶音把和弦摊满整小节（16 分音符扫） | Arpeggio 轨 3393 音符、100% 落在网格、力度恒 100 |
| 4 | **空间拆散** | 一组音在一起 | 一个和弦的音跨多轨 | Chords Harmonies 84 音符 vs Omnisphere 1836 音符 |
| 5 | **低音独立** | 低音=和弦最低音 | 低音轨单独走：持续音、下行、八度跳 | `C6/E → Am9/E → Cmaj9/D → Em7/D → Fmaj7/C`——斜杠和弦泛滥 |
| 6 | **音区** | 一个八度内 | 11 半音 ～ 58 半音（**跨度差 5 倍**） | NSB Pad `C5–C6`（11 半音）；Damascus `A2–G7`（58 半音，约 5 个八度） |
| 7 | **冗余** | 无 | 完全重复的音符（同 pitch/start/dur/vel）成堆 | Arpeggio 轨里同一音重复 3–9 次 |
| 8 | **元数据** | — | 文件名 BPM/调性 ≠ 文件内容 | NSB 文件名写 92，文件**没有 tempo 事件**；`Am_110bpm` 实测是 C 大调 0.91 > A 小调 0.70 |
| 9 | **人性化** | 100% 量化 | 程序化 100% 网格+恒定力度；真人 51–82% 网格+力度 54–127 | Lofi 51% 在网格；JustJazz 82%、时值短到 52 ms |

## 4. 写作手法清单

### 4.1 和声的呈现方式（同一个和弦的 7 种写法）

| 手法 | 在 MIDI 里的样子 | 陷阱 | 对策 |
| --- | --- | --- | --- |
| 柱式（block chord） | 所有音同一 tick 起音 | 最好识别 | 直接进识别 |
| 半柱式（Charleston / stab） | 正拍 + 反拍两次 | 反拍那次会被当成"换和弦" | 短段吸收 |
| 分解和弦（broken） | 低-高-中-高 循环 | 每个音一个 onset | 聚合 |
| 琶音器（arpeggiator） | 16 分音符匀速扫，力度恒定 | 每格只有 1–2 个音，逐格识别必碎 | **按小节/和弦事件聚合，不按拍** |
| Pad 长音 | 一整小节甚至更长的持续音 | 跨小节持有时会被算进相邻段 | 用"活动音集合"而非"onset 集合" |
| 点状 stabs | 时值 50–300 ms 的短和弦 | 起音密集、易与装饰音混淆 | 按"同一拍内同组音"合并 |
| 分层叠置 | 低音 + 中声 + 高音层，共 8 音 | 音级集合爆炸 → 斜杠和弦泛滥 | **折叠到基础和弦 + 延伸 + 低音** |

### 4.2 声部组织

| 手法 | 表现 | 要点 |
| --- | --- | --- |
| 单轨多声部（钢琴左右手） | 一轨跨 4–5 个八度 | 按**时值**分层比按音区可靠（见下） |
| **多轨同通道** | 5 条轨全在 ch1 | **只能用轨道号分角色，不能用 MIDI 通道** |
| 分层同音重复（supersaw / 多采样叠层） | 同 pitch/start/dur/vel 重复 N 次 | 视为一个音，别抬高复音度 |
| 八度加倍（octave doubling） | 同音高类上下八度 | 去重到音高类时匹配，但**音区信息要保留** |
| **旋律叠在伴奏上** | 和弦音**长**、旋律音**短而零散**——采样包里最常见的混装形态 | **按时值 + 同起点聚簇区分**。不要靠音区：旋律会上下跑，音区判断不可靠 |
| 旋律长音 | 偶尔有持续 1–2 拍的旋律音（长音、保持音） | 时值判据失效，要用"声部连续性"兜底：看它前后是否构成一条线 |
| 点状和弦（stabs） | 和弦本身只有 50–300 毫秒 | 会被时值判据误当成旋律，靠"同一起点有多个音"救回来 |
| 贝斯与和弦同轨 | 低音与和弦在同一轨 | 低音要单独识别（转位的生命线） |
| 和弦工具生成的固定音程 | 每个音都 +4、+7（Chord MIDI effect） | 会产生"平行和弦"，不是真实和声进行，注意别当模进 |

### 4.3 时间与力度

| 手法 | 表现 | 对策 |
| --- | --- | --- |
| 量化到 1/16 或 1/32 | 起点 100% 在网格 | 直接信任网格 |
| Humanize（微偏移） | 起点偏离网格 1–4 tick，82%～51% 在网格 | 先吸附再分析；吸附容差随 PPQ 缩放 |
| Swing / 三连音 | 反拍偏移 ≈ 1/6 拍 | 网格要支持 1/3 细分 |
| 切分（syncopation） | 和弦换在反拍 | 分段边界优先权不能只看强拍 |
| 极短时值 | 52–323 ms 的点状和弦 | 别按"时值短所以是装饰音"一刀切 |
| Gate / sidechain 断音 | 和弦被切成 1/16 的碎片 | 时间上相邻的碎片要合并 |
| 延音踏板（CC64） | 音在物理上继续响 | 判断持续性时读 CC64，不只看 note-off |
| 恒定力度 | 全部 100（程序化） | 力度作为特征权重应降低 |
| 力度动态大 | 54–127（真人） | 力度可辅助判断"重音/和弦起点" |

### 4.4 音区与 voicing

| 手法 | 例 | 分析含义 |
| --- | --- | --- |
| 窄叠置 | `C5–C6` 的 pad（11 半音） | 常缺根音，根音要靠低音轨推断 |
| 宽叠置 | `C3–E6`（40 半音） | 跨度过大时先怀疑"两层" |
| Drop voicing / 开放排列 | 音域被拉开 | 音程结构比排列顺序更可靠 |
| 十度排列 | 左手 `1 + 10` | 低音与三音相隔一个八度，是常见识别点 |
| 无根音（rootless） | 左手只弹 `3-7`、`3-5-7-9` | 见上一份文档 §2.10，**必须支持根音推断** |
| 强力和弦（只有 1+5） | 摇滚/808 | 无三音，不能判定大小调 |
| 单音/双音 | 贝斯轨、808 低音 | **拒答**，不出和弦名 |

### 4.5 和声语汇上的常见写法

| 手法 | 说明 | 分析难点 |
| --- | --- | --- |
| 持续低音（pedal） | 低音不动，上方换和弦 | 每个切片都变成斜杠和弦 |
| 半音下行低音 | `C - B - Bb - A` | 低音不属于任何和弦，需"低音维度"独立 |
| 固定循环 vamp | 2 或 4 小节的 loop 反复 | 大量重复段，需去重展示 |
| 调式色彩（Dorian/Lydian） | 借调式音而不离调 | 与"离调"难区分，需滑窗调性 |
| 副属/离调（V7/x） | 临时主音化 | 需要局部调性状态 |
| 平行和声（planing） | 整组和弦同结构平移 | 会被误认成模进/调性游移 |
| 五度圈/三度循环 | 和弦按固定音程循环 | 调性判定会摇摆，需全局解码 |
| 音阶限定（Scale lock） | 所有音在选定音阶内 | 调内但可能非功能，功能分析要给"调内非功能" |

### 4.6 文件与元数据层面的坑（最容易踩，也最容易修）

| 坑 | 实测 | 处理 |
| --- | --- | --- |
| **没有 tempo 事件** | NSB / Lofi / Arp #1 都缺 | 按 SMF 默认 120；**优先采用文件名/BPM 字段**并提示"文件未写速度" |
| 文件名 BPM ≠ 文件 tempo | 常见 | 不要静默相信任何一方，两者都输出 |
| 文件名调性 ≠ 实际调性 | `Am_110bpm` → C 大调 0.91 | 文件名只作先验，不作结论 |
| PPQ 不统一 | 96 / 384 / 480 都出现 | 网格必须按 PPQ 自适应，别硬编码 480 |
| format 0 vs 1 | 大量 loop 是 fmt0 | 两条都要支持；fmt0 也可能塞多声部 |
| 空 conductor 轨 | 轨0 无通道无音符 | 跳过，别当"空文件" |
| 轨道名带插件名 | `TruePianos #3 1`、`Omnisphere 03 (D)` | 可作音色线索，但**不能**作角色判据 |
| 打击乐轨（ch10） | JustJazz 1119 音符 | 必须剔除，否则鼓音高污染和弦 |
| 厂商私有 meta | 常见 | 读长度跳过，别报错 |
| 完全重复音符 | 同 pitch/start/dur/vel ×3–9 | 去重，但**不要**因此改变"和弦音数"统计 |
| 弯音（pitch bend） | JustJazz 每轨 68–162 条 | 音高可能不落在标准音上 → 先按 note-on 的 key 值分析 |
| 空文件/极短文件 | 最小的若干文件 < 0.1 KB | 明确报"没有可用音符"，不要输出空分析 |

## 5. 怎么把它们的和弦分析出来

### 5.1 预处理（顺序不能换）

```text
解析 → tempo map（缺则用文件名/120 并标注）→ 量化（容差按 PPQ 缩放）
→ 剔除 ch10 与纯打击乐轨 → 判角色（文件名 + 轨道名 + 音域 + 音符密度 + 复音度）
→ 分声部（低音区 / 中声区 / 高声区，或按轨）
→ 去重（完全重复音；八度加倍只保留音高类）
```

**角色判据**（实测可用，可作为初值，需按真实语料再校准）：贝斯 = 音域集中在 C3 以下且复音度 ≈ 1；
和弦 = 复音度 ≥ 3 且音域跨度适中；琶音 = 音符密度 > 8/小节且 100% 在 16 分网格；旋律 = 单声部且音域在上方。

### 5.2 时间聚合：窗口不能固定

| 材料 | 固定 1 拍窗口 | 固定 1 小节窗口 | 自适应 |
| --- | --- | --- | --- |
| 柱式 loop | 好 | 会抹平半小节换和弦 | 需要 |
| 琶音轨 | **碎成几百个假和弦** | 碰巧对（实测 Zenhiser 得到 `Cm→G#→D#→F`） | 必须 |
| 极稀疏和声层 | 大量空窗 | 好 | 需要 |
| 切分 comping | 边界错位 | 会抹平 | 必须 |

> 结论：**固定窗口一定会在一类素材上失效**。要的是"活动音集合 + 边界候选 + 全局最优"
> （见 [MIDI 扩展调研](./和弦识别与MIDI扩展调研.md) §3.5）。

### 5.3 折叠：从"音级描述"到"人话和弦名"（最重要的一步）

实测 `Cymatics Bonus MIDI - Am_110bpm` 的输出是：

```text
C6/E → Am9/E → Cmaj9/D → Em7/D → Fmaj7/C
```

技术上每个都"不算错"，但**音乐人会说这是 `C - Am - F`**。所以输出必须分两层：

| 层 | 内容 | 给谁看 |
| --- | --- | --- |
| **精确层** | 实际发声音集合、低音、转位/斜杠 | 调试、比对 |
| **折叠层** | 基础和弦 + 延伸音 + 低音（`C`、`Am`、`F`） | 用户 |

折叠规则（建议）：去掉不属于"基础三和弦 + 七音"的延伸音 → 若低音属于基础和弦则去掉斜杠 →
若低音不属于则保留斜杠 → 结论里同时给"精确写法"和"常用写法"。

**没有这一步，功能在真实素材上就是不可用的**——用户看到 `Cmaj9/D` 只会觉得工具坏了。

### 5.4 用文件名做弱真值，自动跑回归

49% 的文件名带调性、30% 带 BPM、59% 带角色。可以：

```text
文件名 → (role, key, bpm) → 
  role 用于选"该不该分析和弦"
  key  用于校验调性判定（记录不一致率，不直接判错）
  bpm  用于校验 tempo 解析（文件无 tempo 时必须回退到它）
```

配套指标用 `mir_eval` 的 root / majmin / mirex / seg（见上一份调研 §5.1）。

### 5.5 什么时候该拒答

| 情形 | 行为 |
| --- | --- |
| 全程只有 1 个音在响 | 报"单声部，无和弦信息" |
| 只有 2 个音且音程稳定 | 报音程/强力和弦，不给和弦名 |
| 音域跨 > 3 八度且密度高 | 先要求"选择分析哪一轨/哪一区"，别直接输出 |
| 文件无音符 / 解析失败 | 明确报错，不返回空结果 |
| 置信度全线 < 阈值 | 输出"无法确定"，附最佳猜测与理由 |

## 6. 本仓库的测试语料

17 个文件、约 100 KB，按"能否直接分析和弦"分成四个目录（`01-柱式和弦` / `02-琶音` /
`03-单声部` / `04-完整编曲`），每个都记录了实测特征和已知雷点。
清单见 [testdata/midi/语料清单.md](../testdata/midi/语料清单.md)。

建议的用法：

1. `01-柱式和弦` 6 个文件 → 手工标真值，作为 P0/P1 回归基线；
2. `02-琶音` → 专门测"窗口自适应"，固定窗口在这里必错；
3. `03-单声部` → 测"拒答"，这是最容易被忽略、也最能体现产品质量的一条；
4. `04-完整编曲` → 测分轨与多声部，别指望一次全对，要能"逐轨给出结果"。
